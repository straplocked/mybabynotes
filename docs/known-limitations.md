# Known limitations & candidate roadmap

Honest list of what's missing, stubbed, or deliberately deferred — the starting backlog for post-trial iteration. Nothing here is a bug; they're scope lines we drew. (Items fixed during the 2026-09-02→05 batches have been removed; `git log docs/known-limitations.md` has the history.)

## Things a user will notice

- **Anything email needs SMTP.** Invites and password reset both work only with SMTP configured (see operations.md "Enabling email"); without it the inviter shares the on-screen code by hand, and a forgotten password takes the admin running `babylog:reset-password` (operations.md "Admin commands").
- **Amounts are oz/ml only.** Household-synced unit setting; storage and sync stay oz, so ml renders round to the nearest 5 ml. The comp's `timeStep` and `smartPrefill` props remain unexposed.
- **Home timeline shows the last 12 entries**, and stats tiles plus the bar charts stay on a fixed 7-day window — day drill-down pages back to the oldest logged day, but there's no month/calendar view.
- **The History charts are a household pick, not a personal one.** Which of the seven bar charts show up is stored in `settings.charts` like the Now cards are, so both parents get the same History — one of you can't keep diapers-per-day while the other watches naps. Only sleep is measured (hours a day); the other six count entries, so "how many ounces a day" still lives in the stats tiles rather than a chart.
- **Entry types are fixed** (bottle, nursing, pump, wet, dirty, both, sleep, tummy time, bath, meds). No custom types and no free-text notes on entries; sleep's optional Nap/Night tag is the only per-entry label, and there's no equivalent on the other types. (Households *can* switch off pump/diapers/sleep/tummy-time/bath/meds tracking and rename the daily med, but can't add types.)
- **Translations are unreviewed.** The UI ships in 15 languages and the server now matches it (push copy per device, validation and API errors per request, emails per account), but only English is first-party — the other 14 catalogs on each side are machine translations no native speaker has read, and none were checked in-layout, so a long string can still wrap badly on a narrow phone. Language is a per-device pref (never a household setting), so two phones in one household can disagree.
- **A few surfaces stay English**, some by choice and some by omission: an invite email goes in the **inviter's** language (the invitee has no account yet to have a preference); Home Assistant's MQTT entity names and state values (`nurse`, `wet`, `none`) are wire identifiers that HA automations key on, so they're deliberately untranslated; and names and free text people type — children, members, the note on a handoff ask — are data, so they render exactly as written.
- **Fonts load from Google's CDN.** `index.html` pulls Nunito and Material Symbols from `fonts.googleapis.com`; the service worker caches them, so only the first load on a fresh device touches a third party — but an instance that must make *no* outbound requests would need the fonts vendored into the image. The Content-Security-Policy nginx sends allows exactly those two hosts (`fonts.googleapis.com` for stylesheets, `fonts.gstatic.com` for font files) and no other third-party origin; vendoring the fonts means dropping them from the policy too ([operations.md](operations.md#content-security-policy)).
- **A nap's row time and its "Slept" card disagree, on purpose.** Every entry reads at the moment it *started* — sleep and tummy time stamp the wake-up on the wire, and the UI subtracts the duration to place them — but the "Slept" since-card, the "Last nap ended" handoff row and the wake-window insight deliberately keep measuring from the **end**, because the open wake window is the number you act on. So a nap can sit at 3:00 AM in the timeline while its card reads "1h ago · 4:30 AM". (While a sleep timer is *running* the card shows that session instead, so the disagreement only ever concerns naps that have ended.) Integrations see the raw wake-up stamp ([integrations.md](integrations.md#entry-semantics)).
- **Whose duty it is isn't visible on Now.** The header's shift button is icon-only; its accessible name says "Your shift" / "Sam's shift", which a screen reader or a desktop hover gets and a phone tap does not. The footer shortcut that used to spell it out in words is gone (two openers labelled differently was worse), so on a phone you open the sheet to find out. "Next up: feed in 40m" is likewise no longer glanceable — a pending ask gets a pulsing dot and an incoming one gets its own card, but nothing else surfaces.
- **A live since-card and a running-timer card say the same thing twice.** With the default `timerSpot` of "both", a running nap shows as a top timer card, a "Sleeping now" since-card, and a Today row. Deliberate for now — each answers a different question — but it's three copies on a small screen, and `timerSpot` ("top"/"today"/"both") doesn't govern the since-card.
- **Resuming a sleep swallows the stir, and that inflates sleep-per-day.** Resume re-opens the nap from where it began, so every minute the baby was awake in between is counted as sleep — right for a five-minute stir, wrong for a 40-minute one, and there's no "minus the awake bit" anywhere. Deliberate: "down at 7, up at 11" is how a night actually reads. But the awake gap is real minutes, so the sleep-per-day stat and the sleep chart run high for households that resume often, and nothing on those surfaces says so. The button's remaining limits: only the most recent sleep, only for the selected child, only once it has reached the server, and never while a sleep timer is already running for that child.
- **Resume is app-only.** `/api/v1`, the MCP tools, MQTT and the Home Assistant buttons can start and stop timers but can't re-open a sleep; a resumed timer stopped from one of those surfaces just clears, leaving the entry as it was.
- **Offline indicator is subtle** — a small "· offline" in the header, plus a dimmed dot on queued rows.
- **Undo is one-shot**: only the single most recent add/edit/delete, and only while its toast is up.
- **The Baby Buddy import is partial by design** — feedings (bottle/nursing), pumping, changes, sleep, and tummy time map over; solid/parent-fed feedings and the models with no counterpart here (notes, temperature, weight, height, head circumference, BMI) are counted as skipped and reported, never imported. Re-importing the same export is idempotent (ids are derived), but there's no undo for an import beyond deleting entries one at a time.

## Multi-member / multi-child edges

- **The daily meds nudge is household-level** — one dose tracked, not per child. (Feed reminders *do* have per-child intervals.)
- **Shifts are household-level** ("who has the kids"), not per child. The shift sheet's drafted plan and "Right now" rows read the currently selected child's rhythm; there's no explicit per-child or all-children framing in the sheet.
- **Members removed before 2026-09-04** have no name snapshot in `households.former_members`, so their old entries render without an attribution chip. Not recoverable.
- **Stopping someone else's nursing timer loses the side.** Any member can now stop any timer, and the logged entry stays credited to whoever ran the session — but the Left/Right pick is remembered *per device*, against the timer id, so a phone that didn't start the session doesn't have it and the entry falls back to the default side. Fixable by moving the side onto the server timer; it wasn't worth widening the timer wire for. (`/shifts/plan` needs no ownership check either — it only ever touches the caller's own active shift.)

## Shift-system edges

- **"Until she wakes" and open-ended shifts arm nothing** by design — only a clock-time "until" resolves to a real timestamp and a once-only "shift over" push.
- **A handoff ask can't be withdrawn.** Once you've asked, the only ways out are someone accepting it or you handing back (which cancels any pending ask). Until then the header's shift button reads "Waiting for {name}" and the sheet offers a re-ask, which refreshes the request and re-pings — there's no `/shifts/cancel`.
- **A shift you started yourself has no self-serve end.** Hand-back is only offered when someone handed you the shift (`requester_id`), because on a self-started one it would move duty to a partner who never agreed to it. So a self-started shift ends when someone else takes over — by accepting your ask, or by starting their own, which supersedes yours. Two consequences: the `shifts` row stays `active` in the database (harmless; `/state` only carries the latest), and no handback report is generated for it, so the summary card only ever comes from a shift that was handed to you.
- **An addressed ask isn't reserved.** `target_id` narrows the *push* to one person; anyone in the household can still answer it. Deliberate — at 3am you want whoever is awake to be able to take the baby — but it means "I asked the night carer" is a nudge, not a lock.
- **Plan items carry no detail** — a planned feed can't say "4 oz" and planned meds can't name a dose; an item is a type and a time, matched against the first logged entry of that type. Detail lives on the entry you log, not on the plan.
- **A pending ask hides your own active shift**, because `/state` carries a single shift row and the `requested` one is newest. Asking for relief mid-shift swaps your live checklist for the waiting card; the plan is intact (it's still on the server shift) and comes back when the ask is answered. Fixing it properly means either two shift keys on the wire or stamping the ask onto the active row — both break the incoming-ask card on installed clients that haven't updated.
- **Receiving duty doesn't open a shift for you.** `handback` (and member removal) move `on_duty_user_id` without creating a `shifts` row, so the receiver gets the start card and taps once to begin. Deliberate: `started_at` is what the shift report is measured from, so it should be a moment someone chose.
- **Carry-forward only rescues non-feed items.** Unfinished doses ride into the next shift's draft; unfinished *feeds* are dropped on purpose, since the next feed is re-predicted from the last one that actually happened. A skipped feed therefore leaves no trace in the plan — only in the log.
- **Quiet-hours pings are dropped, not deferred** — a "shift over" (or reminder) that lands inside quiet hours never arrives.
- **Push edges**: iOS needs the app installed to the Home Screen before push is offered, and notifications deep-link to the app root (no per-kind screen).
- **Push endpoint validation resolves DNS once, at subscribe time.** `/push/subscribe` rejects private, loopback, link-local and CGNAT destinations (literal or resolved), but a relay hostname that later re-points at a LAN address (DNS rebinding) would steer a subsequent send there. Accepted: the payload is end-to-end encrypted, the request carries no credentials beyond the VAPID JWT for that endpoint, and it times out in 5s.

## Technical debt / release gates

- **CA's scanner flags `api/phpunit.xml`.** The Community Apps listing shipped 2026-09-08, but its repository scan reports `not_unraid_application: 1` — Laravel's test config, picked up purely because it is XML in the repo. Non-blocking and cosmetic; the only clean fix is moving the template to a templates-only repo, which isn't worth it. Details in [docs/ca-submission.md](ca-submission.md). (The Home Assistant add-on has no equivalent listing gap — HA's built-in store carries official add-ons only, and third-party ones are distributed exactly as this one is, by adding a repository.)
- Rate limits (nginx's zones and Laravel's auth throttles alike) key on the direct peer unless `TRUSTED_PROXIES` is set (operations.md "Remote access") — an unconfigured reverse-proxy setup, including the Home Assistant add-on behind ingress, gets instance-wide caps, which is safe but coarse.
- Frontend tests (`npm test`, Vitest) cover the support modules (`s`, `fx`, `base`, `api`, `i18n`, the Baby Buddy importer), the app-shell flows (auth, boot-from-cache, offline, outbox flush, the source offer), the multi-timer Now screen, the duty/shift states on Now (`src/test/shifts.test.jsx`), and the two lazy-loading settings cards (API tokens, Home Assistant). Of the log sheet, the drag, the sleep/tummy stamp arithmetic and the Advanced day control are pinned; still uncovered: the rest of the sheet's paths, the History drill-down, and the report sheet. The class-component + `renderVals()` structure was chosen for design fidelity; extracting screens into components would make the rest testable.
- History rewrite note: pre-2026-09-02 commit SHAs changed when the leaked dev key was scrubbed. Old clones must re-clone.
